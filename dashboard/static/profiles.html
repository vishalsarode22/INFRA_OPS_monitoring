Profiles

What each system is checked for, how often, and who gets told
A system can be watched more than one way at once — a short check every couple of hours, and a full sweep once a day. They need different T-codes, frequencies and destinations, so each is its own profile.

A profile only decides where its monitoring report (PDF + Excel) goes. Alerts — a value over its limit, reminders, SYSTEM DOWN, RCA — never use the lists below: they go to the system's Basis team and Basis manager (Systems page → Edit → "Who gets mails"), at the moment they happen. The full picture per system is on the Alert history page under "Who gets which mail?".

Alert routing by severity

Sender accounts

Each account is a mailbox or WhatsApp sender. A profile picks which one it uses, so PRD alerts need not arrive from the same address as QAS noise.

Passwords and tokens are stored in .env under a key derived from the account id and are never sent back to this page. Leave blank to keep.

Default sender (.env fallback)

Passwords and tokens are written to .env and are never sent back to this page — you will see configured or not configured, never the value. Leave a secret field blank to keep the current one.

That is the same rule this project already applies to system credentials. A password that round-trips through a browser ends up in the DOM, then in a screenshot, then in a ticket.
